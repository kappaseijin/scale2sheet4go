# scale2sheet Go Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 既存 scale2sheet の製品挙動と運用契約を Go 実装へ移植し、Go バイナリを対象に受け入れテストを全件成功させる。

**Architecture:** `cmd/scale2sheet` は引数と終了コードだけを扱い、製品の責務は `internal/{config,domain,sources,sheets,service,pipeline,scheduler,installation,auth,cli}` に分ける。外部 API、filesystem、process、clock は interface/port の後ろに置き、純粋ロジックを table-driven test で先に移植する。

**Tech Stack:** Go 1.22、Go standard library、`google.golang.org/api`、`golang.org/x/oauth2`、`go test`、`go vet`、既存の shell/Python acceptance harness。

**Spec:** `docs/superpowers/specs/2026-08-13-go-port-design.md`

## Global Constraints

- 製品バイナリ名は `scale2sheet` とし、既存の `run`、`pipeline`、`serve`、`auth`、`install`、`uninstall`、`doctor` コマンドを維持する。
- 終了コードは構文・引数エラー `2`、設定/実行時エラー `1`、正常終了 `0` を維持する。
- `~/.config/scale2sheet/settings.json` と環境変数の優先順位（環境変数 > settings.json）を維持する。
- status JSON、入力 snapshot、run lease、30 秒の Sheets 操作期限、launchd の既存パスと時刻を維持する。
- 受け入れテストは Go バイナリを対象に実行し、狭い focused test を全体検証の代用にしない。
- テスト追加・変更では、正しい入力で通ることと壊した入力で落ちることを両方確認する。
- scale_exporter、agmsg、herdr-agent-monitor のリポジトリは変更しない。
- Issue #2 の範囲を超える別課題が見つかった場合は、別 Issue・別 PR として記録し、混ぜない。

## 実施状態（2026-08-13）

Task 1〜8 の Go 実装、Task 9 の Go acceptance harness と現行資料移行、Task 10 のローカル検証（2026-08-13T14:28:06+09:00）まで完了した。
Go の正式経路は `CGO_ENABLED=0 go build` / `go test` であり、旧 TypeScript のソース・テスト資産は比較履歴として残しているが、package の既定 test/build と acceptance から参照しない。
旧資産の削除は Go の利用者契約とは別の cleanup 課題になるため、本 Issue #2 では混ぜない。

最終 PR 作成・self-check・main 同期は Task 10 の残作業である。
