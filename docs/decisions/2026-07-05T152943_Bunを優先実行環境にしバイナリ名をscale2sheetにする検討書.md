# Bunを優先実行環境にし、バイナリ名をscale2sheetにする検討書

## 背景

[Ph.12の検討書](./2026-07-05T105321_単一バイナリ化_bun_buildを正式な配布形態にする検討書.md)では、「配布・運用（launchd、エンドユーザー向け成果物）はBun単体バイナリを正式経路とする一方、開発・型検査・テストはNode.jsツールチェインを維持する」という境界を採用した。この境界自体はPR #9〜#12で実装済み。

その後ユーザーから追加の明確な指示があった。

1. Bunで単一バイナリアプリを作る手順をREADME.mdに明記する
2. `build:bun`が生成するバイナリ名を`scale2sheet-bun`から`scale2sheet`へ変更する
3. このプロジェクトが生成する実行環境は、Node.jsよりBunを優先とする
4. 3に準拠して資料（ドキュメント）を整備する

指示3「Node.jsよりBunを優先」をどう解釈し、既存のPh.12境界（開発ツールチェインはNode.js維持）とどう整合させるかが本検討の主題。

## 採用した案

**案A: 「優先」を配布・実行時の既定/推奨経路の明示として扱う。開発時のツールチェイン（`npm test` / `npm run typecheck`、vitest）はNode.jsのまま変更しないが、ドキュメント上の書き方・実行手順の並び順・生成物の名前は、すべて「Bunが第一候補、Node.jsは代替/開発時手段」という扱いに統一する。**

具体的な変更点:

| 対象 | 変更前 | 変更後 |
| --- | --- | --- |
| バイナリ名 | `dist/scale2sheet-bun`（`build:bun`が生成） | `dist/scale2sheet`（同スクリプトが生成先を変更） |
| `scripts/run-pipeline.sh` | `dist/scale2sheet-bun`を参照 | `dist/scale2sheet`を参照するよう追従 |
| README「インストール」手順 | Node.js手順（`npm install && npm run build && node dist/index.js`）が先頭、Bunは後日追加予定 | Bun手順（`bun install`または`npm install` → `bun build --compile` → `./dist/scale2sheet`）を主経路として先頭に配置。Node.js手順は「開発・デバッグ用」の代替として後段に残す |
| EXTERNAL_DESIGN.md / ARCHITECTURE_DESIGN.md | Node.js実行を前提にした記述 | 配布・実行環境としてはBunバイナリを優先する旨を明記。CLI仕様自体（コマンド/オプション）はランタイムに依存しないため変更なし |
| 開発・テストツールチェイン | `npm test` / `npm run typecheck`（vitest, tsc） | **変更しない**。zod/Bunランタイムの相互運用性が完全solved でない領域（[Ph.11検討書](./2026-07-05T102021_Bun_CLI化についての検討書.md)参照、コンパイル済みバイナリでは非再現だが`bunx --bun vitest`実行では既知の問題が残る）があるため、開発・CI相当の検証はNode.jsツールチェインに残し、実行環境（配布物）の優先度のみをBunへ引き上げる |

採用理由:

- ユーザーの指示3・4の文言（「生成する**実行環境**」）は配布・実行時のランタイムを指しており、開発時のテスト・型検査ツールチェインとは区別できる。Ph.12で判明したzod/Bunの相互運用性の懸念（実行バイナリでは非再現だが、テストランナー経由では既知の問題）を踏まえると、開発・CIの検証手段まで無理にBunへ統一するのはリスクを持ち込むだけで、ユーザーの指示の範囲を超える
- バイナリ名を`scale2sheet`にすることで、CLIの`program.name("scale2sheet")`（`src/cli/index.ts`）およびnpm packageの`bin`名`cale2sheet`との対応が取れ、配布物として自然な名前になる
- README・設計書の並び順・書き方だけで「優先度」を表現できるため、既存のPh.11/Ph.12で決めた技術的境界（開発ツールチェインはNode.js）を壊さずに指示を満たせる

## 却下した案

### 案B: 開発・テスト・CIのツールチェインもBunへ完全統一する（`bun test`、`bunx tsc`等へ置き換え）

却下した理由: [Ph.11の検討書](./2026-07-05T102021_Bun_CLI化についての検討書.md)で、`bunx --bun vitest run --run`実行時に`zod`関連で4スイートがFAILする既知の問題が残っている（コンパイル済みバイナリでは非再現だが、テストランナー経由では未解決）。ユーザーの指示は「生成する実行環境」の優先度についてであり、開発ツールチェインの完全統一までは求めていないと判断した。無理に統一すると、解決していない既知の相互運用性問題を新たに開発フローの前提に持ち込むことになりリスクが高い。

### 案C: バイナリ名は`scale2sheet-bun`のまま変更せず、READMEの記述順だけを入れ替える

却下した理由: ユーザーが指示2で名前変更を明示的に求めているため、指示に反する。また、実行環境がBunへ優先されるなら、その配布物の名前に`-bun`という実装詳細（ビルドツール名）が残っているのは利用者にとって不自然（利用者は`scale2sheet`というコマンドを使いたいのであって、`-bun`サフィックスに意味を見出す必要はない）。

### 案D: Node.js実行手順（`npm run build && node dist/index.js`）をREADMEから完全に削除する

却下した理由: 開発・デバッグ時にはNode.js経路（tsc・vitestとの組み合わせ）が引き続き有用であり、[Ph.12の検討書](./2026-07-05T105321_単一バイナリ化_bun_buildを正式な配布形態にする検討書.md)で「Node実行は開発・デバッグ用の経路として残す」とすでに決めている。ユーザーの指示は「優先度をBunにする」ことであり、Node.js経路の完全撤去までは求めていないと判断した。
