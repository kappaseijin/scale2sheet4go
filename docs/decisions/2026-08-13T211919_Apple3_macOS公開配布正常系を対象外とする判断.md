# Apple=3 — macOS公開配布正常系を対象外とする判断

## 判断の根拠

Issue [#10](https://github.com/kappaseijin/scale2sheet4go/issues/10) のユーザーコメントで、Apple=3 が選択された。これにより、Developer ID署名、Hardened Runtime、公証、staple、Gatekeeper正常系受入は本プロジェクトの対象外とする。

## 採用する境界

- `scripts/build-macos-release.sh` による unsigned universal local artifact と、既存の install / doctor / LaunchAgent / uninstall 契約は対象内に維持する。
- `scripts/build-macos-distribution.sh` と `scripts/run-macos-distribution-contract-acceptance.sh` は、秘密情報なしで fail-closed 境界と誤った identity・部分出力を検査する契約資産として維持する。
- `.github/workflows/macos-release.yml` は公開配布を実行する通常経路ではなく、secret を通常 CI へ渡さない境界の資料・契約資産として扱う。
- Developer ID証明書、Apple Developer Program、notary credentials の取得・投入・保管は行わない。

## 対象外となる受入

次の正常系は受入テストの合格条件から除外し、credentials 不在を blocker として扱わない。

- Developer ID identity での binary / DMG 署名
- Apple notary service への `notarytool submit --wait` と `Accepted` 確認
- DMG の ticket staple、Gatekeeper、mounted binary の実機検査

秘密情報なしの contract acceptance がこれらを代替することはない。contract acceptance は、対象外経路が誤って unsigned・Apple Development・ad hoc へフォールバックせず、出力を作らずに失敗することを検査する。

## 資料と Issue の扱い

Issue #37 で README、PLAN、受入報告、関連設計・計画の状態をこの判断へ同期する。同期後、Issue #10 は「正常系受入を対象外とした」理由を記録して close する。将来この方針を変更する場合は、新しいユーザー判断と別 Issue を起点にする。
