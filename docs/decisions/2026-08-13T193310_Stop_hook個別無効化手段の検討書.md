# Stop hook 個別無効化手段の検討書

## 背景

Issue #28 で、ユーザーの `cc-status` と `security-guidance@claude-plugins-official` の Stop hook が Codex の Stop 出力契約に適合せず、`invalid stop hook JSON output` の原因になり得ることを確定した。
Issue #29 では Stop だけを止め、Stop 以外の既存 hook とプラグイン本体を維持する必要がある。

## 目的の妥当性

ターン終了ごとのエラーを除去しつつ、コード探索 gate、状態表示、セッション処理、security-guidance の Stop 以外の検査を残すことは、パイロット運用の継続性と安全性の両方に必要である。
Go アプリの実装変更で解決する問題ではないため、アプリの Issue と分離した運用設定 Issue #29 として扱う。

## 外部調査

Codex 0.147.0 の app-server `hooks/list` で有効 hook とキーを取得できる。
非 managed hook の無効化は `config/batchWrite` の `hooks.state` へ対象キーと `enabled: false` を upsert する公式経路である。
再有効化は同じキーへ `enabled: true` を upsertする。

参照:

- [Codex app-server protocol（hooks/list / config/batchWrite）](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md)
- [Codex hooks](https://developers.openai.com/codex/hooks/)

## 採用した案

Codex app-server の `hooks/list` で現在のキーを取得し、次の2件だけを `config/batchWrite` で `hooks.state` に `enabled: false` として upsertする。

| 対象 | hook key | 変更後 |
| --- | --- | --- |
| `cc-status` | `/Users/kappa/.codex/hooks.json:stop:0:0` | disabled |
| security-guidance | `security-guidance@claude-plugins-official:hooks/hooks.json:stop:0:0` | disabled |

`preToolUse`、`postToolUse`、`sessionStart`、`sessionEnd`、`userPromptSubmit`、`permissionRequest` などの別イベントキーは変更しない。
プラグインキャッシュの `hooks.json` と hook 実体も変更しない。

## 却下した案

### 案A: プラグインキャッシュを直接編集する

却下した理由: プラグイン更新で失われ、管理対象の成果物を変更する。Codex の個別 state による無効化という公式経路に反する。

### 案B: `~/.codex/hooks.json` から Stop 登録を削除する

却下した理由: `cc-status` の宣言を消すと再登録時の差分とロールバックが追跡しにくい。状態を disabled として残す方が、キー・対象・再有効化方法を保持できる。

### 案C: hooks 機能または全 hook を停止する

却下した理由: Stop 以外のコード探索、セッション、通知、権限制御の hook まで失われ、Issue #29 の目的を超える。

### 案D: Codex 用 wrapper を追加する

却下した理由: wrapper の JSON 変換と保守範囲を新たに作る。ユーザーが選択した Stop=1 の最小変更ではない。

## ロールバック

同じ `hooks.state` の2キーへ `enabled: true` を upsertし、`hooks/list` で両方が enabled に戻ったことを確認する。
ロールバックでも hook 宣言・プラグインキャッシュ・Stop 以外の状態は変更しない。
